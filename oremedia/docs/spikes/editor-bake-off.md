Specification: section 22 Phase 0 ("editor bake-off on two real brand fixtures (Konva vs. Polotno if licence allows)";
gate "one fixture document round-trips save → reopen → render with pixel diff under threshold"), section 11.5
(rendering and fidelity) and 11.6 (editor adapter).

## Fixture brands

Both are the golden-render fixtures (`packages/editor/src/renderer/fixtures.ts`), each with its own pinned font that
ships with the repository under `tooling/test-fixtures/fonts` (both SIL OFL, licence files beside them). Nothing was
downloaded.

| Brand                                 | Script and direction  | Font                                | Document                                                                                                                                                                               |
| ------------------------------------- | --------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `latin_feed_square` (`square_1080`)   | Latin, left to right  | Karla (variable, `Karla[wght].ttf`) | Very large JPEG cover-cropped into a rounded mask, explicit crop in a circle, translucent rotated panel, justified wrapped body, a rotated group, a clipped caption, a protected logo. |
| `arabic_story_9x16` (`ig_story_9x16`) | Arabic, right to left | Noto Naskh Arabic (variable)        | Right-aligned wrapped Arabic headline, centred Arabic body with Western digits and `%`, Latin label with tracking, circle-masked photo, protected reversed mark.                       |

Limit: the repository ships no Devanagari or CJK font, so those scripts are not covered (spec 11.5 names CJK "where a
brand needs them"). Adding one means committing an OFL font file under `tooling/test-fixtures/fonts` and a third
fixture; the tests below are written per fixture and pick it up.

Fixed in this change: the fixtures' element ids were not valid prefixed ULIDs (they contained `I`, `L`, `O`, `U`,
which Crockford base32 excludes), so neither golden document could be saved through the creative module
(`CreativeDocumentV1` rejected them). The ids were corrected; ids do not reach pixels, and both goldens still match
with 0 differing pixels (`golden.integration.test.ts`, run after the change).

## Gaps (open)

Each gap is a test marked `fails` (vitest `it.fails`) that asserts the correct behaviour, so it turns red, and the
marker has to come off, on the day it is fixed.

1. **Arabic run inside a Latin-first line with tracking (or `justify`)**: Konva draws a non-RTL paragraph grapheme by
   grapheme whenever `letterSpacing ≠ 0` or `align = justify` (`konva/lib/shapes/Text.js`, "Keep RTL text in one
   native run"). An Arabic run in such a line is drawn letter by letter: unjoined and in logical order (pixel-identical
   to the same letters with every join broken). RTL-first paragraphs are not affected. Test:
   `GAP: an Arabic run inside a Latin-first line with tracking is shaped (…)`. Fix options: draw mixed-direction lines
   as one native run using canvas `letterSpacing` (Konva already does this for RTL), or refuse tracking/justify on
   mixed-script text in validation. Either changes pixels for some documents, so it is a MINOR renderer version with
   regenerated goldens (`packages/editor/src/renderer/version.ts`).
2. **`align: justify` on an RTL paragraph draws left-aligned** (pixel-identical to `align: left`): Konva skips
   justification for RTL and falls back to its default alignment. Test: `GAP: align=justify on an Arabic (RTL)
paragraph is justified or at least right-aligned (…)`. Minimal fix: map `justify` to `right` for RTL in
   `scene.ts` (MINOR renderer version).
3. **Closed: static contrast check read text over shapes as 1:1.** `validateAgainstBrand` compared text colour with
   the page background only, so the Latin badge text and the Arabic body on the ribbon were blocking `contrast` before
   render and an agent batch on these documents would have been refused. It now walks down the paint order under each
   text (`backdropsFor` in `packages/editor/src/validate.ts`): opaque rects take the part of the text box they cover,
   ellipses show their colour without hiding what is beneath, covering images and the page background take the rest,
   and translucent fills or shapes tilted against the text mark what lies beneath as obscured. A failure is blocking
   only against a resolved colour under at least 10 % of the text box; otherwise it is a warning and the render check,
   which measures the pixels, decides. Tests: `static contrast uses what is actually under the text (spec 11.4)` in
   `validate.test.ts`; both golden fixtures now validate with nothing blocking (`bake-off.test.ts`, the round trip).
4. **Scripts not covered**: Devanagari and CJK (no font in the repository; see Limit above).
5. **Keyboard operability on the Arabic brand in the built studio**: the studio e2e seeds the Latin editor fixture;
   the Arabic fixture is covered DOM-free only. The keyboard code path is script-independent, so the risk is low.

## Recommendation

Keep Konva behind `EditorAdapter` (spec 11.6 default). It meets every property the bake-off measures on a Latin and
an Arabic brand, with deterministic exports and a studio/worker pixel match; the three rendering and validation gaps
above are specific, reproducible and fixable inside `packages/editor` without changing the adapter contract. The
Polotno question stays with D-05.
