# Runbook: revoke a compromised credential, API client, skill or template

**Owner:** tenant owner/admin; platform on-call for platform-level secrets. **Exercised:** locally by `apps/worker-core/src/runbooks.integration.test.ts` ("revoke a compromised credential (7.10)"): an API key stops working on `access.apiClients.rotate`, every key of a principal on `access.servicePrincipals.revoke`; `publishing.channels.disconnect` shreds the credential (ciphertext and wrapped key empty, `destroyed_at` set, the broker refuses it) and holds the scheduled publication; a role change (`access.members.setRole`) revokes the member's sessions. **Needs a live environment for:** the secret manager and KMS rotation, redeploys, and notifying brands. Skill and template retirement and a direct "revoke all sessions" have no API procedure yet (below).

| What                                           | Action                                                                                                                                                          | Effect                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API client key                                 | `access.apiClients.rotate` (or `servicePrincipals.revoke` for all keys of a principal)                                                                          | Old key hash rejected immediately (`UNAUTHENTICATED`); audited                                                                                                                                                                                                                                                                                                                                              |
| Social token                                   | `publishing.channels.disconnect { channelConnectionId, expectedVersion }`                                                                                       | Credential row crypto-shredded in the same transaction (`destroyed_at`, wrapped data key and ciphertext overwritten), connection `disabled`, every `scheduled` publication on it `held` with reason `channel_active`, `channel.disconnected` emitted; the running `tokenRefreshWorkflowV1` reads the row and exits. Exercised by `publishing.integration.test.ts` ("disconnect destroys the credential …"). |
| Session                                        | `access.members.setRole` (a role change) or removing the membership revokes the member's sessions; there is no `access.sessions.revokeAll` procedure yet (open) | Cookies/bearers rejected on next request                                                                                                                                                                                                                                                                                                                                                                    |
| Skill version                                  | No `skills.versions.retire` procedure yet (the machine has `retire`; open): publish the previous version again so bindings pin it                               | Future runs pin the previous version; history untouched                                                                                                                                                                                                                                                                                                                                                     |
| Template version                               | No `creative.templates.retire` procedure yet (the machine has `retire`; open)                                                                                   | No new documents from it; existing revisions untouched                                                                                                                                                                                                                                                                                                                                                      |
| Platform secret (KMS key, provider app secret) | Rotate in the secret manager (`KMS_KEY_ID_CREDENTIALS`, `PROVIDER_<KEY>_CLIENT_ID_REF` / `_SECRET_REF`), redeploy affected services                             | Only worker-core / worker-ingest hold a decrypting KMS (`createKmsFromEnv({ decrypt: true })`); the API is composed with `WrapOnlyKms` and cannot open a credential even with the row. A KMS key change needs a re-wrap job (not built yet: report)                                                                                                                                                         |

Always: record the incident (docs/operations/incident-process.md §7; there is no `operations.incidents` procedure yet), check the audit trail for use of the credential after the suspected exposure (`operations.audit.query { actorId }`), and notify affected brands.
